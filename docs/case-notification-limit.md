# 사례: iOS 예약 알림 64개 한도와 스케줄러

## 문제
iOS는 앱 하나가 미리 예약해 둘 수 있는 로컬 알림을 **64개**까지만 유지한다.

Check Again은 할 일마다 "알림 → 다시 알림 1 → 다시 알림 2"가 주기마다 반복된다. 할 일 10개에 주기 몇 번만 미리 깔아도 한도를 넘는다. 넘친 알림은 조용히 버려지고, 사용자는 알림이 왜 안 왔는지 알 수 없다.

## 선택지
| 방법 | 문제 |
|---|---|
| 할 일마다 다음 알림 하나만 예약 | 다시 알림이 사라진다. 체크하지 않으면 다음 주기까지 아무 일도 없다 |
| iOS의 반복 알림(repeats) 사용 | 반복이 달력 기준이라 "완료 기준"을 표현할 수 없다 |
| 서버 푸시 | 서버 비용, 유료 멤버십, 오프라인 문제. 이 앱에는 과하다 |
| **모든 할 일의 알림을 합쳐 가장 가까운 64개만 예약** | 먼 미래 알림은 그 전에 다시 계산되므로 손해가 없다 |

## 설계

```
할 일 A: 9:00  9:10  9:20 │ 다음 날 9:00 ...
할 일 B:    9:05          │ ...
할 일 C:          9:30    │ ...
           ↓ 시간순으로 합치고
      9:00 9:05 9:10 9:20 9:30 ... (앞에서 64개)
           ↓
      iOS에 예약 (나머지는 다음 재계산 때)
```

1. 할 일마다 `upcomingFires(anchor:now:limit:)`로 앞으로 울릴 알림을 시간순으로 만든다. 오래 밀린 할 일은 지나간 주기를 건너뛰고 지금 이후부터 만든다.
2. 전부 합쳐 시간순으로 정렬하고 앞에서 64개만 남긴다.
3. **언제 다시 계산하나**: 데이터가 저장될 때(`ModelContext.didSave`)와 앱이 활성화될 때. 저장이 연달아 일어나도 0.3초 기다렸다가 한 번만 계산한다.
4. **중복 방지**: 알림 식별자를 "할 일 ID + 시각"으로 만든다. 전체를 지우고 다시 넣어도 같은 알림이 두 번 생기지 않는다.
5. **정리**: 다시 계산할 때 이미 체크한 할 일의 받은 알림은 알림 센터에서 지운다. 아직 안 한 일의 알림만 남긴다.

```swift
public static func plan(_ items: [Item], now: Date, limit: Int = systemLimit,
                        quietHours: QuietHours? = nil) -> [Request] {
    let requests = items.flatMap { item -> [Request] in
        var seen = Set<Date>()
        return item.upcomingFires(now: now, limit: limit).compactMap { fire in
            let date = quietHours?.adjusted(fire.date) ?? fire.date
            guard seen.insert(date).inserted else { return nil }   // 방해 금지로 모인 알림은 하나만
            return Request(routineID: item.routineID, fire: ReminderFire(date: date, kind: fire.kind))
        }
    }
    return Array(requests.sorted { $0.fire.date < $1.fire.date }.prefix(limit))
}
```

## 검증
- 단위 테스트: 기본 한도가 64개인지, 여러 할 일이 시간순으로 합쳐지는지, 오래 밀린 할 일이 지금 이후 알림부터 이어지는지, 다음 주기를 넘는 다시 알림은 버리는지.
- 시뮬레이터: 앱을 켜면 로그에 "알림 64개 예약"이 찍히고, 1분 뒤로 잡은 시험용 할 일의 알림이 정시에 오는 것을 확인했다.

## 나중에 드러난 문제
- **위젯에서 체크한 경우**: 위젯은 별도 프로세스라 앱의 재계산이 돌지 않는다. 그대로 두면 이미 한 일에 알림이 울린다. 재계산 코드를 앱·위젯 공통(`Shared`)으로 옮겨 위젯 버튼도 같은 방식으로 다시 예약하게 했다.
- **체크해도 알림 센터에 알림이 남는 경우**: 앱 안에서 체크할 때 SwiftData 자동 저장에 맡기고 있었다. 저장이 늦으면 재계산과 정리도 늦었다. 체크 직후 바로 저장하도록 고쳤다.
- **새벽 알림**: 완료 기준이라 새벽에 체크하면 다음 알림도 새벽이다. 방해 금지 시간을 스케줄러 단계에 넣어, 어느 경로로 재계산하든 같은 규칙이 적용되게 했다.
