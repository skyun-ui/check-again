# AI와 함께 일한 방식

Check Again은 AI 코딩 도구(Claude Code)와 함께 만들었다. 이 문서는 "AI가 만들어 줬다"가 아니라 **무엇을 내가 판단했고, 무엇을 AI에게 맡겼는지**를 기록한다.

## 역할 나누기

| 내가 정한 것 (제품 판단) | AI에게 맡긴 것 (실행) |
|---|---|
| 무엇을 왜 만드는가: 완료 기준 반복 | 구현, 단위 테스트 작성 |
| 다시 알림의 원칙: "스트레스가 되면 안 된다" → 주기에 비례, 최대 2번 | 일정 계산 엔진 설계와 경계 조건 테스트 |
| 위젯의 역할: "브레인 아웃소싱", 해야 할 일만 때가 되면 | 위젯 확장, App Group 이전과 데이터 마이그레이션 |
| 체크 취소는 "시작 전"으로 | 실기기 크래시 로그 분석, 시작 시간 측정 |
| "적어 둔 건 해야 할 일" → 시작 전 할 일도 위젯에 | 기술 제약 조사 (64개 알림 한도, 쓰기 전용 캘린더 권한 등) |
| 미리 알림과 같은 사용감, 이름 Check Again, 아이콘 콘셉트 | 화면 구현, 시뮬레이터 스크린샷으로 확인 |
| 용어: "목록 모음"은 뜻이 맞으니 유지 | 문서화, 커밋 기록 |

## AI의 제안을 받아들이지 않은 경우
- **체크 취소 동작**: AI는 기존 일정을 지키려고 "직전 완료 시점으로 복귀"로 구현했다. 실제로 써 보니 취소가 안 된 것처럼 보였고, 원래 요청대로 "시작 전"으로 바꾸게 했다. → AI가 요청을 바꿔 해석할 때는 먼저 묻게 하는 규칙으로 이어졌다.
- **위젯 체크 옵션**: AI는 "위젯 편집" 안의 설정으로 만들었다. 나도 그 옵션이 있는 줄 몰랐다는 사실이 근거가 되어 위젯 두 종류로 나눴다.
- **용어 "목록 모음"**: AI는 화면 제목과 다르다며 "첫 화면"으로 바꾸자고 했다. 목록들을 모은 화면이라는 뜻이 맞다고 판단해 유지했다.
- **깃발 기능**: 미리 알림의 기능을 모두 넣고 싶었지만, 실제로 많이 쓰는지 데이터가 없어서 AI의 추정 근거를 듣고 보류했다. 베타 사용자에게 물어서 정하기로 했다.

## AI가 놓친 것을 잡아낸 장치
- **실기기에서 직접 써 보기**: 위젯이 자리표시 화면으로 깨지는 것, 체크해도 알림이 남는 것, 위젯을 눌러도 늦게 열리는 느낌은 모두 내가 실제로 쓰다가 발견했다.
- **측정 요구**: "Debug라서 느릴 것"이라는 그럴듯한 설명 대신 측정을 하게 했고, 가설이 틀렸다는 걸 확인했다. → [사례](case-launch-time.md)
- **매 변경마다 테스트와 설치**: 테스트 52개, 저장 구조를 바꿀 때마다 실기기 데이터 사본으로 이전 확인.

## 기록
- 모든 결정은 이유와 함께 문서(설계 결정, 작업 일지)에 남겼다.
- AI와의 대화 원문은 세션이 끝날 때 개인 정보를 가린 형태로 자동 보관되도록 설정했다. 어떤 판단이 어디서 나왔는지 나중에 확인할 수 있다.

## 정리
AI 덕분에 혼자서도 이틀 만에 실제 기기에서 쓰는 앱을 만들었다. 하지만 무엇을 만들지, 어디까지가 "좋은 경험"인지, 언제 멈추고 측정할지는 사람이 정해야 했다. AI는 판단을 대신하지 않고, 판단을 빠르게 검증하고 실행하는 도구였다.
